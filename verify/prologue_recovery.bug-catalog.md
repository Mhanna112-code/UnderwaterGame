# Recovery presentation and checkpoint contract

Public surface: recovery copy, visible saving/retry/Continue button, focus and
actual input; canonical checkpoint confirmation remains owned by World.

| ID | Failure | Oracle |
| --- | --- | --- |
| REC-001 | A bare instruction/stock button fails to communicate a deliberate second-chance beat after Cordys. | Inspect actual ready/saving/error renders at wide, narrow and tall sizes; no extra mandatory time or text wall. |
| REC-002 | Redesigned hierarchy hides/wraps motivation or clips the action/error on a small screen. | Actual rendered Control bounds, full motivation/error copy, focused visible action and screenshot/OCR review. |
| REC-003 | Decoration blocks clicks or lets Continue release play before durable saving. | Real mouse/keyboard input in saving, retry and ready states plus actual World denied-write/retry/Load/death journey. |
| REC-004 | A fixed-coordinate browser test mistakes a moved button for broken recovery or silently clicks elsewhere. | Locate the actual rendered action through OCR and click it; require resulting public phase/save behavior. |
| REC-HARNESS-005 | A post-click polling attempt overwrites the clicked-card screenshot with a blank transition, hiding the actual visual evidence despite functional success. | Retain numbered attempts; canonical evidence is only an image containing the rendered action used for the real mouse click. Inspect its full card and preserve failed attempts. |

No additional narrative exposition, timed gate, screen flashing or gameplay
redesign. Decorative geometry is not proof of beauty; inspection can reject a
passing layout test. Save-owner tests remain independent of presentation.
